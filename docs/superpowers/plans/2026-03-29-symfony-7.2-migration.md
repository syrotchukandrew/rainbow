# Symfony 6.4 → 7.2 Migration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Rainbow project from Symfony 6.4 LTS to Symfony 7.2 LTS with all 49 tests passing.

**Architecture:** Symfony 7 drops annotation support entirely — all Doctrine ORM, Gedmo, and Validator annotations in entities must become PHP 8 attributes. Controllers already use `#[Route]` attributes. Config and bundle version bumps are required. The console command needs `#[AsCommand]`.

**Tech Stack:** PHP 8.2, Symfony 7.2, Doctrine ORM 2.x, doctrine/doctrine-bundle ^2.11, stof/doctrine-extensions-bundle ^1.12, friendsofsymfony/jsrouting-bundle ^3.5

## Task 4: Update AddUserCommand to use #[AsCommand]

**Files:**
- Modify: `src/AppBundle/Command/AddUserCommand.php`

Symfony 7 deprecates `->setName()` in `configure()` for commands — `#[AsCommand]` is the required way.

- [x] **Step 1: Add attribute and remove setName/setDescription from configure()**

Replace the class declaration and configure method:

```php
use Symfony\Component\Console\Attribute\AsCommand;

#[AsCommand(
    name: 'app:add-user',
    description: 'Creates users and stores them in the database',
)]
class AddUserCommand extends Command
{
    // ...

    protected function configure(): void
    {
        $this
            ->setHelp($this->getCommandHelp())
            ->addArgument('username', InputArgument::OPTIONAL, 'The username of the new user')
            ->addArgument('password', InputArgument::OPTIONAL, 'The plain password of the new user')
            ->addArgument('email', InputArgument::OPTIONAL, 'The email of the new user')
            ->addOption('is-admin', null, InputOption::VALUE_NONE, 'If set, the user is created as an administrator')
        ;
    }
```

Symfony 7 drops `doctrine/annotations`. All `@ORM\*`, `@Gedmo\*`, `@Assert\*` docblock annotations must become PHP 8 `#[...]` attributes.

**Mapping reference:**

| Annotation | Attribute |
|-----------|-----------|
| `@ORM\Entity(...)` | `#[ORM\Entity(...)]` |
| `@ORM\Table(...)` | `#[ORM\Table(...)]` |
| `@ORM\Column(...)` | `#[ORM\Column(...)]` |
| `@ORM\Id` | `#[ORM\Id]` |
| `@ORM\GeneratedValue(...)` | `#[ORM\GeneratedValue(...)]` |
| `@ORM\ManyToOne(...)` | `#[ORM\ManyToOne(...)]` |
| `@ORM\OneToMany(...)` | `#[ORM\OneToMany(...)]` |
| `@ORM\ManyToMany(...)` | `#[ORM\ManyToMany(...)]` |
| `@ORM\JoinColumn(...)` | `#[ORM\JoinColumn(...)]` |
| `@ORM\JoinTable(...)` | `#[ORM\JoinTable(...)]` |
| `@ORM\OrderBy(...)` | `#[ORM\OrderBy(...)]` |
| `@ORM\HasLifecycleCallbacks` | `#[ORM\HasLifecycleCallbacks]` |
| `@Gedmo\Slug(fields={"f"})` | `#[Gedmo\Slug(fields: ['f'])]` |
| `@Gedmo\Blameable(on="create")` | `#[Gedmo\Blameable(on: 'create')]` |
| `@Gedmo\Timestampable(on="create")` | `#[Gedmo\Timestampable(on: 'create')]` |
| `@Gedmo\Tree(type="nested")` | `#[Gedmo\Tree(type: 'nested')]` |

| `@Gedmo\TreeRight` | `#[Gedmo\TreeRight]` |
| `@Gedmo\TreeLevel` | `#[Gedmo\TreeLevel]` |
| `@Gedmo\TreeRoot` | `#[Gedmo\TreeRoot]` |
| `@Gedmo\TreeParent` | `#[Gedmo\TreeParent]` |
| `@Gedmo\Translatable` | `#[Gedmo\Translatable]` |
| `@Gedmo\Uploadable(...)` | `#[Gedmo\Uploadable(...)]` |
| `@Gedmo\UploadableFilePath` | `#[Gedmo\UploadableFilePath]` |
| `@Gedmo\UploadableFileName` | `#[Gedmo\UploadableFileName]` |
| `@Assert\NotBlank(...)` | `#[Assert\NotBlank(...)]` |
| `@Assert\Length(...)` | `#[Assert\Length(...)]` |
| `@Assert\Email(...)` | `#[Assert\Email(...)]` |

**Pattern — before:**
```php
/**
 * @ORM\Column(name="title", type="string", length=255)
 * @Assert\NotBlank(message="estate.title.blank")
 */
private $title;
```

**Pattern — after:**
```php
#[ORM\Column(name: 'title', type: 'string', length: 255)]
#[Assert\NotBlank(message: 'estate.title.blank')]
private $title;
```

**Class-level — before:**
```php
/**
 * @ORM\Table(name="estate")
 * @ORM\Entity(repositoryClass="AppBundle\Repository\EstateRepository")
 */
class Estate
```

**Class-level — after:**
```php
#[ORM\Table(name: 'estate')]
#[ORM\Entity(repositoryClass: EstateRepository::class)]
class Estate
```

## Task 6: Update stof_doctrine_extensions config for AttributeReader

- [x] **Step 1: Update stof config**

Add `use_attribute_reader: true` (or equivalent for stof ^1.12):

In `config/packages/stof_doctrine_extensions.yaml`:

```yaml
stof_doctrine_extensions:
    default_locale: uk
    orm:
        default:
            tree: true
            sluggable: true
            blameable: true
            uploadable: true
            timestampable: true
```

Note: stof ^1.12+ auto-detects attribute readers when `doctrine/annotations` is not present. No extra config is needed. If deprecation warnings about annotation reader remain, ensure `doctrine/annotations` is removed from `composer.json` require.

## Notes

### If composer update fails on bundle conflicts

- `hwi/oauth-bundle ^2.0` — check latest: may need `^2.x` patch for SF7
- `php-http/httplug-bundle ^1.19` — check if a `^2.0` is needed
- `knplabs/knp-paginator-bundle ^6.0` — may need `^6.x` latest patch
- Run `docker compose exec web composer why-not symfony/symfony 7.2` to identify blockers

### doctrine/annotations removal

Symfony 7 no longer requires `doctrine/annotations`. Once entities use attributes, it can be removed. Some Gedmo behaviours (uploadable, translatable) must also use attribute-based config — verify in `stof/doctrine-extensions-bundle` changelog for v1.12+.

### Gedmo attribute namespace

Gedmo attributes live in `Gedmo\Mapping\Annotation` — the same namespace as before, but now used as PHP 8 attributes. The `use Gedmo\Mapping\Annotation as Gedmo;` import stays unchanged.
